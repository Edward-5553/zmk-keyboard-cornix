# Cornix dongle display

Display widgets vendored from [englmaxi/zmk-dongle-display](https://github.com/englmaxi/zmk-dongle-display)
at commit `2bb333f87136d33e94a49d86236ed9ec254a8060` (MIT; see LICENSE).
This distinct `cornix_dongle_display` shield avoids relying on external shield
search order and keeps the customized animation in this repository.

Local changes:

- Rename the shield; retain upstream widget configuration symbols for compatibility.
- Replace Bongo Cat images with 64×64 Salary Cat indexed monochrome frames,
  pre-scaled 2× from the original 32×32 pixel artwork without runtime transforms.
- Keep animation state per widget and initialize the image immediately.
- Default: loop `cat-idle.gif` at 10 fps (3 frames).
- A physical key-down immediately selects `cat-error.gif` at 10 fps (4 frames).
  Every press extends the active deadline; 3000 ms without a press restores idle.
  Releases, host key repeat and encoder rotation do not extend the deadline.
  Key presses from both halves, including modifier/layer keys, count together.
- A shared LVGL timer checks activity every 20 ms. Event callbacks only record
  timestamps under a spinlock; LVGL calls stay on the display thread. Repeated
  states do not restart animation. WPM is optional and does not select animations.
- Use a black 64×128 portrait layout. A compact USB/BT/OFF column and fixed L/R
  battery rows share the top, with equal 18-pixel heights and aligned baselines.
  An 84-pixel animation region contains the 64×64 cat; the footer shows the layer.
  Modifier/lock widgets are disabled by default; explicit legacy opt-in replaces
  the layer footer. The 4×6 and 5×7 fonts are generated by
  `scripts/generate-dongle-fonts.py` from the approved pixel design.
  See [layout and hardware checks](../../../docs/dongle-portrait.md).
- SH1106 remains 128×64 in devicetree. A local flush adapter rotates each dirty
  rectangle clockwise and converts I1 pixels to vertical, LSB-first pages.
  It preserves partial updates and both pixel polarities, using a fixed 1 KiB
  buffer and synchronous writes on the display queue. Zephyr 4.1's stock mono
  flush does not rotate pixels when only LVGL's rotation setting is changed.
- L/R rows are fixed independently of pairing/source order. Side identity is
  learned from a source's physical key position on the Cornix layout (left x
  <= 600, right x >= 750). After dongle startup, press a normal key on each half.
  Unknown/unreported readings show `--%`; zero is a visible valid percentage.
  No learned mapping is written to flash. Optional dongle battery adds a D row.
- Give the battery container a fixed width and place both label and icon at
  nonnegative positions. Text aligned to the left of a tiny icon inside an
  auto-width container was clipped. The regression checks assert label bounds.
- Keep all battery sources in each snapshot so coalesced updates retain both
  halves' readings and labels, including when pairing order is reversed.
- Compare battery and modifier state before queuing display work. Ordinary key
  presses/releases no longer queue updates when the displayed state is unchanged.
  Battery rendering compares each row with its last rendered state; an update to
  one half does not redraw the other. All LVGL calls remain on the display thread.
- Run the dedicated display task every 20 ms. Cat frames remain 100 ms apart;
  input switches at the next eligible display tick and idle resumes after 3 s.

Only rebuild/flash `cornix_dongle_nosd.uf2` for this display-only change.
No settings reset or half firmware update is needed for an already paired setup.

Rebuild images with Pillow:

```sh
python scripts/encode-dongle-cat.py --source-dir /path/to/original/gifs
```

Generated C images are committed; firmware builds do not need Pillow or a GIF decoder.
See ASSETS.md for the exact source files and artwork attribution.

Hardware checks: follow [the portrait checklist](../../../docs/dongle-portrait.md).
Verify readable L/R labels, a single key triggering active animation, the 3-second
idle deadline, long layer names, USB/BT switching, header alignment, display wake
and no stale pixels.

GitHub Actions runs `scripts/test-dongle-cat.py`, `scripts/test-dongle-battery.py`
and `scripts/test-dongle-portrait.py` with a host compiler. They exercise real
widget/flush code using stubs. Tests cover both source orders, bounded visible
labels, unknown and zero readings, change filtering, coalesced updates, single
press activation, deadline extension, long uptimes, rotation/polarity/stride,
partial writes, bounds and error completion. Full ZMK builds and hardware display
validation remain separate checks.
